# Research: выбор биржи для v1

Дата проверки всех фактов: **2026-10-27** (если не указано иное). Источники — официальная документация бирж и официальные репозитории SDK. Пометка **[не подтверждено]** — факт не удалось проверить по первоисточнику в этой сессии; его нужно проверить руками на testnet/demo до PLAN или в первом тикете.

## 1. Вопрос и затронутые требования

Какую криптобиржу взять для v1 (спот + линейные USDT-перпетуалы) — Bybit V5, Binance (Spot + USDⓈ-M Futures) или OKX V5 — с учётом качества testnet/demo и того, насколько нативно API закрывает требования SPEC.

Затронутые требования: FR-1 (правила инструментов), FR-2 (происхождение ордеров), FR-4 (reduce-only), FR-5 (amend, cancel, cancel-all по инструменту), FR-6 (SL/TP позиции), FR-7 (закрытие позиции), FR-8 (плечо), FR-10 (локальная валидация шагов/минимумов), FR-13 (notional), FR-26/27 (идемпотентность, неизвестный результат), FR-28 (классификация ошибок), FR-34/35 (rate limits), FR-48 (граница цены market-ордера), FR-49 (проверка прав ключа), NFR-2 (ручные проверки против testnet), NFR-5 (вторая биржа без изменения правил).

## 2. Факты с источниками

### 2.1 Bybit V5

**Среды.**
- Testnet: `https://api-testnet.bybit.com`, отдельный аккаунт на отдельном сайте; ключи создаются в testnet API management ([Integration guidance](https://bybit-exchange.github.io/docs/v5/guide)). Тестовые монеты запрашиваются со страницы Assets не чаще раза в 24 часа, доступ к testnet — только из браузера на ПК ([Help Center: How to Request Test Coins on Testnet](https://www.bybit.com/en/help-center/article/How-to-Request-Test-Coins-on-Testnet) — это help center, не API docs).
- Demo trading: REST `https://api-demo.bybit.com`, WS только private `wss://stream-demo.bybit.com`; публичные данные — с mainnet `wss://stream.bybit.com`. Demo — изолированный модуль внутри **mainnet**-аккаунта (свой UID), «basic trading rules match real trading», ордера хранятся 7 дней, «not every API is available for demo trading account» (список недоступных не приведён), WS Trade не поддерживается, rate limits — дефолтные, повысить нельзя ([Demo Trading Service](https://bybit-exchange.github.io/docs/v5/demo)).
- Средства на demo — через API: `POST /v5/account/demo-apply-money`, 1 запрос/мин, до 100000 USDT за запрос (также BTC 15, ETH 200, USDC 100000), `adjustType=1` уменьшает баланс ([Demo Trading Service](https://bybit-exchange.github.io/docs/v5/demo)). Это позволяет автоматизировать подготовку ручного набора проверок (NFR-2).

**Единый API.** Один набор эндпоинтов для spot и linear, различие — параметр `category=spot|linear` ([Place Order](https://bybit-exchange.github.io/docs/v5/order/create-order)). Подпись HMAC_SHA256 (или RSA), заголовки `X-BAPI-API-KEY`, `X-BAPI-TIMESTAMP`, `X-BAPI-SIGN`, `X-BAPI-RECV-WINDOW` (default 5000 мс); строка подписи `timestamp + api_key + recv_window + queryString|jsonBody` ([guide](https://bybit-exchange.github.io/docs/v5/guide)).

**SDK.** `pybit` — «Official Python3 API connector», поддерживается сотрудниками Bybit, Python ≥ 3.10, основан на `requests` и `websocket-client` (то есть синхронный) ([GitHub pybit](https://github.com/bybit-exchange/pybit)). Последний релиз **5.16.0 от 18 Apr 2026** ([releases](https://github.com/bybit-exchange/pybit/releases)). Поддержка demo-домена в pybit на странице README не упомянута [не подтверждено].

**Торговые операции.**
- Создание: `POST /v5/order/create`. `reduceOnly` (linear), `closeOnTrigger`; при `reduceOnly=true` нельзя ставить TP/SL; `qty="0"` + `reduceOnly` + `closeOnTrigger` закрывает позицию до maxOrderQty. `timeInForce`: GTC, IOC, FOK, PostOnly, RPI; market всегда IOC. Для spot market buy по умолчанию `qty` в quote, `marketUnit=baseCoin|quoteCoin` ([Place Order](https://bybit-exchange.github.io/docs/v5/order/create-order)).
- Защита цены market: `slippageToleranceType=TickSize|Percent`, `slippageTolerance` (TickSize 1–10000, Percent 0.01–10), только для market, не для TP/SL/conditional. Bybit сам превращает market в IOC limit; для деривативов порог считается как отклонение от mark price ([Place Order](https://bybit-exchange.github.io/docs/v5/order/create-order); диапазоны изменены 2025-10-09 по [changelog](https://bybit-exchange.github.io/docs/changelog/v5)).
- Amend: `POST /v5/order/amend` по `orderId` или `orderLinkId`; меняются `qty`, `price`, `triggerPrice`, `takeProfit`/`stopLoss` ("0" — снять); только unfilled/partially filled; асинхронно — успешный ответ означает «принято» ([Amend Order](https://bybit-exchange.github.io/docs/v5/order/amend-order)).
- Cancel all: `POST /v5/order/cancel-all`; для linear обязателен `symbol`/`baseCoin`/`settleCoin`; без `orderFilter` отменяет все типы, **включая conditional и TP/SL**; до 500 ордеров за запрос (если больше — случайные 500); для spot по умолчанию только `Order`. Ответ — список `orderId`/`orderLinkId`, асинхронно ([Cancel All](https://bybit-exchange.github.io/docs/v5/order/cancel-all)).
- SL/TP позиции: `POST /v5/position/trading-stop` (category linear/inverse/option, spot не поддерживается): `tpslMode=Full|Partial`, `takeProfit`, `stopLoss`, `trailingStop`, `tpSize/slSize` (Partial), `tpTriggerBy/slTriggerBy`, "0" — снять. TP/SL — системные conditional orders, отменяются при закрытии позиции и следуют за её размером ([Set Trading Stop](https://bybit-exchange.github.io/docs/v5/position/trading-stop)). Ровно модель FR-6.
- Плечо: `POST /v5/position/set-leverage` (`category=linear`, `symbol`, `buyLeverage`, `sellLeverage`; в one-way должны совпадать) ([Set Leverage](https://bybit-exchange.github.io/docs/v5/position/leverage)); повтор того же значения — ошибка `110043 "Set leverage has not been modified."` ([Error codes](https://bybit-exchange.github.io/docs/v5/error)) — её надо трактовать как успех.
- Закрытие позиции (FR-7): отдельного эндпоинта «close position» в проверенных страницах нет; закрытие = `POST /v5/order/create` с `reduceOnly=true` (market или limit IOC).

**Правила инструментов.** `GET /v5/market/instruments-info`: linear — `priceFilter{minPrice,maxPrice,tickSize}`, `lotSizeFilter{minOrderQty,qtyStep,maxOrderQty,maxMktOrderQty,minNotionalValue}`, `leverageFilter{minLeverage,maxLeverage,leverageStep}`; spot — `priceFilter{tickSize}`, `lotSizeFilter{basePrecision,quotePrecision,minOrderAmt,maxLimitOrderQty,maxMarketOrderQty}` (minOrderQty/maxOrderQty у spot deprecated), без leverageFilter; `riskParameters{priceLimitRatioX,priceLimitRatioY}` (формула для linear изменена в мае 2026). Пагинация linear: `limit` до 1000, `cursor`, linear-символов уже > 500; у spot пагинации нет ([Instruments Info](https://bybit-exchange.github.io/docs/v5/market/instrument)). Количество в перпетуалах — в базовой монете (не контрактах).

**Client order id.** `orderLinkId` ≤ 36 символов `[A-Za-z0-9_-]`, «must be unique» (область уникальности — среди всех или только активных — не уточнена [не подтверждено]) ([Place Order](https://bybit-exchange.github.io/docs/v5/order/create-order)). Дубликат отклоняется: `110072 "OrderLinkedID is duplicate"` (деривативы), `170141 "Duplicate clientOrderId"` (spot) ([Error codes](https://bybit-exchange.github.io/docs/v5/error)) — то есть биржа сама даёт защиту от двойного создания при повторе с тем же id. Поиск после таймаута: `GET /v5/order/realtime?orderLinkId=...` — `openOnly` игнорируется при запросе по id, возвращаются и закрытые, но хранится не более 500 последних закрытых на категорию, и после рестарта сервера их надо искать в истории ([Get Open & Closed Orders](https://bybit-exchange.github.io/docs/v5/order/open-order)); `GET /v5/order/history` поддерживает `orderLinkId`, отменённые без исполнения видны только 24 часа ([Get Order History](https://bybit-exchange.github.io/docs/v5/order/order-list)). Коды неизвестного исхода: `10000 Server Timeout`, `10016 Server error`, `170146 Order creation timeout`, `170147`, `170310`, `110079 order is processing` ([Error codes](https://bybit-exchange.github.io/docs/v5/error)).

**Rate limits.** Две модели: IP — 600 запросов / 5 с на IP, превышение — HTTP 403 «access too frequent», ждать ≥ 10 минут (бан снимается сам); UID — per endpoint per second per UID, rolling window, превышение — `retCode 10006 "Too many visits!"`. Лимиты (per UID): create/amend/cancel 10/s, trading-stop 10/s, set-leverage 10/s, realtime orders 50/s, cancel-all — в зависимости от категории. Заголовки на каждый ответ: `X-Bapi-Limit-Status` (остаток по эндпоинту), `X-Bapi-Limit`, `X-Bapi-Limit-Reset-Timestamp` ([Rate Limit](https://bybit-exchange.github.io/docs/v5/rate-limit)). Demo — только дефолтные лимиты ([Demo](https://bybit-exchange.github.io/docs/v5/demo)).

**Права ключа.** `GET /v5/user/query-api` возвращает `readOnly` (0/1), `ips`, `expiredAt`, `isMaster`, `parentUid` и `permissions` по группам: `ContractTrade[Order,Position]`, `Spot[SpotTrade]`, `Wallet[AccountTransfer,SubMemberTransfer,SubMemberTransferList,Withdraw]`, `Derivatives`, `Options` и др. Вывод и переводы — все в группе `Wallet` ([Get API Key Information](https://bybit-exchange.github.io/docs/v5/user/apikey-info)). С 2026-02-10 менять IP ключа через API запрещено ([changelog](https://bybit-exchange.github.io/docs/changelog/v5)). Работает ли `query-api` на demo-домене — [не подтверждено].

### 2.2 Binance (Spot + USDⓈ-M Futures)

**Среды.** Futures: mainnet `https://fapi.binance.com`, тестовая среда `https://demo-fapi.binance.com`, WS `wss://demo-fstream.binance.com` ([USDⓈ-M General Info](https://developers.binance.com/docs/derivatives/usds-margined-futures/general-info)). Spot: Demo Mode `https://demo-api.binance.com/api`, ключ создаётся на demo.binance.com; в отличие от Spot Testnet (баланс сбрасывается ежемесячно, рынок независим от live, иногда новые фичи раньше) у Demo баланс сбрасывается в UI когда угодно, фичи, IP limits и filters «exactly the same as the live exchange», данные рынка «similar to live» ([Spot Demo Mode](https://developers.binance.com/docs/binance-spot-api-docs/demo-mode/general-info)). Пополнение demo через API не нашёл [не подтверждено].

**Раздельные API.** Spot (`/api/v3/...`) и USDⓈ-M (`/fapi/...`) — разные хосты, эндпоинты, модели ордеров и фильтров. SDK — модульный `binance-connector-python`: отдельные пакеты `binance-sdk-spot`, `binance-sdk-derivatives-trading-usds-futures`, Python ≥ 3.10 ([GitHub](https://github.com/binance/binance-connector-python)); версии на странице не указаны [не подтверждено].

**Торговые операции (Futures).**
- `POST /fapi/v1/order`: LIMIT/MARKET, `reduceOnly` (нельзя в Hedge Mode), `newClientOrderId` `^[\.A-Z\:/a-z0-9_-]{1,36}$`, уникален **среди открытых ордеров**; `priceMatch` (OPPONENT/QUEUE…) только для LIMIT; `newOrderRespType=RESULT` возвращает итог market сразу ([New Order](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api)).
- **SL/TP:** с 2025-12-09 все conditional (STOP_MARKET, TAKE_PROFIT_MARKET и др.) перенесены в Algo Service: `POST /fapi/v1/algoOrder` (`algoType=CONDITIONAL`, `triggerPrice`, `closePosition=true` — закрыть всю позицию при срабатывании, `priceProtect`, `workingType`, `clientAlgoId`); старые эндпоинты возвращают `-4120`; «Modification of untriggered conditional orders is not supported»; лимит 200 conditional на все символы; отмена — `DELETE /fapi/v1/algoOrder`, `DELETE /fapi/v1/algoOpenOrders` ([New Algo Order](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/New-Algo-Order), [Derivatives changelog](https://developers.binance.com/docs/derivatives/change-log)). SL/TP как атрибута позиции нет — это отдельные algo-ордера, их надо отменять/заменять самим, и cancel-all обычных ордеров их не трогает.
- Amend: `PUT /fapi/v1/order` — «currently only LIMIT order modification is supported»; с 2026-09-15 добавлен необязательный `reduceOnly` (только для валидации) ([New Algo Order page](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/New-Algo-Order), [changelog](https://developers.binance.com/docs/derivatives/change-log)).
- Max leverage — не в `exchangeInfo`, а в отдельном USER_DATA «Notional and Leverage Brackets» ([Exchange Information](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Exchange-Information)); фильтры символа — `PRICE_FILTER`, лот (`minQty`, `stepSize`), `notional`, `multiplierUp/Down`.
- Поиск после таймаута: `GET /fapi/v1/order` по `origClientOrderId`; не находится, если CANCELED/EXPIRED без сделок и создан > 3 дней назад, или создан > 90 дней назад ([Query Order](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Query-Order)). HTTP 503 «Unknown error…» — статус исполнения неизвестен, «don't treat this as a failure» ([General Info](https://developers.binance.com/docs/derivatives/usds-margined-futures/general-info)).
- Market price protection для обычного market-ордера на futures не нашёл: `priceProtect` — только для триггерных algo-ордеров.

**Spot.** `newClientOrderId` уникален среди открытых; amend — `PUT /api/v3/order/amend/keepPriority` только **уменьшает** qty; иначе `POST /api/v3/order/cancelReplace`; cancel all по символу `DELETE /api/v3/openOrders`; `quoteOrderQty` для market; slippage/price protection для MARKET не описаны ([Spot Trading endpoints](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/trading-endpoints)). Таймаут: `-1007 TIMEOUT` и 5XX — статус неизвестен ([Spot General API Information](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/general-api-information)).

**Rate limits.** Weight **per IP, not per API key** (`X-MBX-USED-WEIGHT-1M`, futures `REQUEST_WEIGHT` 2400/мин в примере), order limits per account (`X-MBX-ORDER-COUNT-10S/1M`), HTTP 429 (+`Retry-After` на spot), повторные нарушения — HTTP 418, бан IP от 2 минут до 3 дней ([Futures General Info](https://developers.binance.com/docs/derivatives/usds-margined-futures/general-info), [Spot General Info](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/general-api-information)). С 2025-10-23 reduce-only и close-position ордера освобождены от throttling `-1008` ([changelog](https://developers.binance.com/docs/derivatives/change-log)).

**Права ключа.** `GET /sapi/v1/account/apiRestrictions`: `ipRestrict`, `enableReading`, `enableWithdrawals`, `enableInternalTransfer`, `permitsUniversalTransfer`, `enableFutures`, `enableSpotAndMarginTrading`, `enableMargin` и др.; указан только mainnet-хост `api.binance.com` ([API Key Permission](https://developers.binance.com/docs/wallet/account/api-key-permission)). Доступен ли на demo/testnet — [не подтверждено] (SAPI на тестовых средах исторически ограничен).

### 2.3 OKX V5

- Demo: тот же REST-домен + заголовок `x-simulated-trading: 1`, WS `wss://wspap.okx.com/ws/v5/...`; ключ demo не истекает; не поддерживаются withdraw/deposit/purchase ([OKX V5 docs](https://www.okx.com/docs-v5/en/)). Пополнение: `POST /api/v5/account/demo-adjust-balance`, increase **3 раза в сутки**, до 5000 USDT за запрос ([там же](https://www.okx.com/docs-v5/en/)).
- Единый API для spot/swap (`instId`, `tdMode`), но **`sz` для деривативов — в контрактах**, notional = `sz × ctVal × markPx` ([там же](https://www.okx.com/docs-v5/en/)) — лишний слой конвертации для FR-10/FR-13.
- `clOrdId` ≤ 32 alphanumeric, уникален среди live/partially_filled, после терминального статуса переиспользуется; `reduceOnly` для SWAP только в net mode, при `sz` больше позиции ордер отклоняется целиком; `attachAlgoOrds` для TP/SL; `slippagePct` (0–0.05) **только для spot/margin market**, деривативный market — по самой агрессивной цене Price Limit Mechanism ([там же](https://www.okx.com/docs-v5/en/)).
- Rate limits: private per User ID (sub-account — свой UID), place order 60/2 с на UID+instId, суммарно sub-account 1000 order requests/2 с (`50061`), превышение — `50011`; заголовки с остатком в документации не нашёл [не подтверждено] ([там же](https://www.okx.com/docs-v5/en/)).
- Права ключа: `GET /api/v5/account/config` → `perm` = `read_only`/`trade`/`withdraw`, `ip` (5 req/2 с) ([там же](https://www.okx.com/docs-v5/en/)). Отдельного признака «transfer» в `perm` нет — для FR-49 это значит, что перевод нельзя отличить отдельно (по документации перевод входит в trade/withdraw [не подтверждено]).
- `POST /api/v5/account/set-leverage` (lever, mgnMode, instId; 20/2 с) — подтверждено. `POST /api/v5/trade/close-position`, algo-ордер с `closeFraction=1` для TP/SL на позицию, mass cancel по инструменту, retention `GET /api/v5/trade/order` по `clOrdId` — в оглавлении есть, но параметры прочитать не удалось (страница документации слишком большая для инструмента) [не подтверждено].

## 3. Варианты и trade-offs

**A. Bybit V5.** Плюсы: один API и одна модель ордера для spot и linear (меньше кода в infrastructure-адаптере, проще NFR-5 — адаптер один), SL/TP как атрибут позиции (FR-6 и AC-1 «поставь стоп на 3% ниже входа» — один вызов, без управления отдельными стоп-ордерами), amend по qty/price, полный набор прав ключа с отдельными Withdraw/Transfer (FR-49 закрывается без fail-closed-костылей), per-UID лимиты с остатком в заголовке на каждый ответ (FR-35 можно реализовать по фактическим данным биржи), отклонение дубликата `orderLinkId` (дополнительная защита FR-26/27 на стороне биржи), demo с программным пополнением (NFR-2). Минусы: demo «not every API is available» без списка; спот и деривативы различаются в полях instruments-info (два варианта валидации FR-10); ответы amend/cancel-all асинхронные — подтверждать состояние запросом; хранение закрытых ордеров в realtime ограничено 500 записями; IP-бан 10 минут при 600/5 с — для multi-tenant с одного IP нужен общий IP-бюджет.

**B. Binance.** Плюсы: самая большая ликвидность и узнаваемость, хорошо документированная семантика «unknown status» (503/-1007), demo с live-фильтрами. Минусы для нашего SPEC: два разных API (spot и futures) — фактически два адаптера; SL/TP — отдельные algo-ордера с 2025-12, не изменяемые до триггера (FR-6 «изменить SL» = отмена + новый, неатомарно); amend только LIMIT на futures и только уменьшение qty на spot (FR-5 частично); weight **per IP** — в удалённом режиме все tenants делят один бюджет, а бан 418 до 3 дней бьёт по всем пользователям сразу (FR-34/35 — главный риск); проверка прав через SAPI может не работать на demo.

**C. OKX V5.** Плюсы: единый API, `perm` в account/config, per-UID лимиты, удобный demo через заголовок. Минусы: деривативы в контрактах (`ctVal`) — источник ошибок в notional и подтверждениях человеку (FR-13, FR-21); `slippagePct` только для spot; пополнение demo 5000 USDT × 3/сутки; часть ключевых эндпоинтов не удалось проверить в этой сессии.

Четвёртого кандидата не добавлял: из проверенных никто не выглядит явно сильнее Bybit по критериям SPEC.

## 4. Рекомендация

**Bybit V5, среда разработки — demo trading (`api-demo.bybit.com`), testnet (`api-testnet.bybit.com`) — как запасной вариант.** Demo предпочтительнее: правила торговли как на live, пополнение по API, публичные данные с mainnet (реалистичные цены для FR-13/FR-48). Testnet держать в конфиге как отдельную среду, если demo не поддерживает нужный эндпоинт. В терминах SPEC «testnet» = тестовая среда биржи; стоит явно записать в PLAN, что для Bybit это demo, а mainnet и demo — разные ключи и разные домены.

**Клиент:** свой async-клиент на `httpx` (подпись HMAC_SHA256 — ~30 строк), а не pybit: pybit синхронный (`requests`), а нам нужны asyncio, точный контроль таймаутов (FR-27), разбор `X-Bapi-Limit-*` (FR-35) и подмена транспорта в тестах без сети (NFR-2, `httpx.MockTransport`). pybit 5.16.0 использовать как эталон подписи/параметров при отладке.

**Решения по требованиям:**
- FR-48: не полагаться на `slippageTolerance` (процент считается биржей от своей опорной цены — для деривативов от mark price, а не от показанной человеку худшей цены). Market-ордер исполнять как **`orderType=Limit`, `timeInForce=IOC`, `price` = худшая цена из подтверждения**, округлённая к tickSize в безопасную сторону — это детерминированно даёт «не хуже показанного, остаток не исполняется» на всех трёх биржах (NFR-5). `slippageTolerance` можно добавить как второй предохранитель.
- FR-26/27: `orderLinkId` генерирует сервер (детерминированно из ключа идемпотентности), при неизвестном исходе — `GET /v5/order/realtime?category=…&symbol=…&orderLinkId=…`, затем `GET /v5/order/history?orderLinkId=…`; повторная отправка с тем же `orderLinkId` безопасна, т.к. дубликат отклоняется кодом 110072/170141 (обрабатывать как «уже создан», затем запросить состояние).
- FR-2: префикс в `orderLinkId` (например `gx-<короткий id>`) помечает «свои» ордера; при 36 символах `[A-Za-z0-9_-]` хватает на префикс + 32 hex/base32. Происхождение ордера дополнительно сверять с собственным журналом (префикс может поставить и внешний бот — поэтому источник истины — журнал, префикс — быстрый фильтр). Для позиций происхождение — по журналу (у позиции нет client id).
- FR-49: `GET /v5/user/query-api`; отклонять, если в `permissions.Wallet` есть любой из `Withdraw`, `AccountTransfer`, `SubMemberTransfer`; `readOnly=1` → профиль чтения; `ips` пустой — предупреждение (и нужна ли политика «требовать IP whitelist на mainnet» — вопрос к PLAN).
- FR-34/35: собственный per-user token bucket ниже per-UID лимитов Bybit + глобальный бюджет на IP сервера (600/5 с) с запасом; обновлять остаток по `X-Bapi-Limit-Status`; на `10006` и HTTP 403 — «повторите через N» по `X-Bapi-Limit-Reset-Timestamp`.
- FR-5 cancel-all: `orderFilter` выставлять явно (иначе на linear снесутся и TP/SL позиции); для подтверждения (FR-21) сначала прочитать открытые ордера, чтобы показать внешние.
- FR-8: `110043` = «уже такое плечо» → успех.
- Позиционный режим: v1 — one-way (`positionIdx=0`), hedge mode — отказ с понятной ошибкой.

**Ключевые эндпоинты Bybit V5** (база `https://api-demo.bybit.com` / `https://api.bybit.com`): правила — `GET /v5/market/instruments-info`; цена/сводка — `GET /v5/market/tickers`; стакан — `GET /v5/market/orderbook`; свечи — `GET /v5/market/kline`; балансы — `GET /v5/account/wallet-balance`; позиции — `GET /v5/position/list`; открытые/недавние ордера — `GET /v5/order/realtime`; история ордеров — `GET /v5/order/history`; сделки — `GET /v5/execution/list`; создать — `POST /v5/order/create`; изменить — `POST /v5/order/amend`; отменить — `POST /v5/order/cancel`; отменить все — `POST /v5/order/cancel-all`; SL/TP — `POST /v5/position/trading-stop`; плечо — `POST /v5/position/set-leverage`; права ключа — `GET /v5/user/query-api`; пополнение demo — `POST /v5/account/demo-apply-money`. Детально проверены в этой сессии: instruments-info, realtime, history, create, amend, cancel-all, trading-stop, set-leverage, query-api, demo-apply-money; остальные (tickers, orderbook, kline, wallet-balance, position/list, execution/list, cancel) взяты из навигации документации и списка demo-эндпоинтов без чтения параметров.

**Что остаётся неизвестным (проверить руками в первом тикете против demo):**
1. Работают ли на demo `GET /v5/user/query-api` и `instruments-info` для spot/linear (документация не перечисляет недоступные эндпоинты). Если `query-api` на demo нет — нужно явное поведение FR-49 для demo (записать в SPEC, как требует FR-49).
2. Область уникальности `orderLinkId` (навсегда или среди активных) и поведение повтора после отмены — от этого зависит, можно ли полагаться на 110072 как на защиту.
3. Опорная цена `slippageTolerance=Percent` на spot (документация описывает mark price только для деривативов).
4. Точная семантика 10000/10016/170146 (создан ордер или нет) — стратегия FR-27 должна считать их «неизвестно» и идти в query.
5. Поддерживает ли pybit demo-домен (для отладки) и версия на момент реализации.
6. Для OKX/Binance — не закрытые пункты таблицы с пометкой [не подтверждено]; на выбор не влияют, но важны для оценки NFR-5.
